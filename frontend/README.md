# Фронтенд «Радар вузов»

Светлая CRM с тёмным меню по скриншотам брендбука, акценты #7700FF и #FF4F12. Короткие анимации учитывают prefers-reduced-motion.

## Запуск

Команды выполняются в `frontend/`. Требуется установленный Node.js и зависимости `npm ci`.

- `npm run dev:mock`: автономное демо на http://127.0.0.1:5173/radar с MSW.
- `VITE_AUTH_MODE=dev npm run dev`: настоящий API с заголовком X-Dev-User. API должен работать на 127.0.0.1:8000 с `AUTH_MODE=dev`.
- `VITE_AUTH_MODE=keycloak npm run dev`: настоящий API и вход через Keycloak.

Параметры перечислены в `.env.example`. При необходимости скопируйте в `.env.local`. При занятом порте остановите прежний Vite в его терминале. Для API на другом адресе настройте VITE_API_BASE_URL и серверный CORS. Пустой адрес использует Vite proxy /api.

Keycloak по умолчанию: http://127.0.0.1:8080, realm radar-vuzov, public client radar-web. Используется Authorization Code с PKCE S256. Токены хранятся только в памяти, обновляются перед запросом. Роль и область доступа поступают из /api/v1/me.

Для production: `VITE_AUTH_MODE=keycloak npm run build`. В production режимы mock/dev запрещены. Vite proxy работает только при разработке; на стенде нужен reverse proxy /api или VITE_API_BASE_URL и CORS. Переменные VITE_* публичны, секреты в них помещать нельзя.

## Что подключено

Профиль, workflow, радар сигналов, список и карточка взаимодействия, переход этапа с expected_version, история, сведения договора, каталог и карточка вуза. Поиск, фильтры и пагинация выполняются запросами. Список разрешённых переходов определяет сервер. Карточка не обновляется автоматически при возврате фокуса или восстановлении сети, чтобы отправлять показанную пользователю версию. Конфликт 409 требует обновления карточки и повторного выбора этапа, автоматической повторной записи нет.

Подключены аналитика, рейтинг с весами, отчёты, импорт с предпросмотром, команда, редактор процессов, каталоги, доступ, настройки, аудит и интеграции. В карточке доступны документы, заметки, участники, состояние и ответственный. Добавлены создание записей, клиенты, контакты, сообщения, уведомления и серверная справка.

Диаграммы главной страницы открывают списки с фильтрами. Списки имеют сохранённые виды, доску текущей страницы и групповые переходы. На телефоне все разрешённые разделы доступны через кнопку бокового меню.

Группы B2B/B2C фильтруют радар и список; этапы загружаются по процессу выбранной группы. Поддерживаются клиенты без вуза и программы без продукта. В MSW клиент «Демо Клиент» доступен Михаилу Волкову и руководителям.

## Контракт и проверки

- `npm run api:generate`: обновить TypeScript-типы из ../contracts/openapi.yaml.
- `npm run api:check`: проверить отсутствие расхождений с контрактом.
- `npm test`: проверка типов контракта и Vitest.
- `npm run build`: TypeScript и production-сборка.

Клиент находится в src/api, авторизация в src/auth, синтетические HTTP-ответы в src/mocks. Точка входа использует ConnectedApp.tsx. App.tsx хранит общие компоненты и метаданные навигации.

MSW имитирует API только в режиме mock. Перезапуск страницы сбрасывает изменения. UUID и временные метки фикстур не обязаны совпадать с seed бэкенда. Это проверка клиента, а не доказательство работы настоящего сервера или защиты данных. Окончательные права всегда проверяет сервер.

Rostelecom Basis подключён локально из переданных командой WOFF2 (Light, Regular, Medium, Bold) в public/fonts. Право публичного распространения Basis не подтверждено: лицензии в переданном наборе нет. Ранее добавленные шрифты и их отдельные лицензии сохранены.
