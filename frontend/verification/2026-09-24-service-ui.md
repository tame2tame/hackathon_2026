# Фронтенд готового API: проверка 24.09.2026

## Основание

Ветка `origin/backend/foundation`, commit `bdf1e34`, подтянута fast-forward в `frontend-1-s03-smoke`. Прочитаны архитектура, контракт, передача бэкенда от 20.09 и `docs/FRONTEND_SCREENS_SPEC.md`. Новые backend-изменения добавляют PDF статистики, изображения справки и документацию; несовместимых изменений старых методов не обнаружено. Это проверка совместимости фронтенда, не независимый аудит всего бэкенда.

## Реализация

- Все прежние пункты «Скоро» подключены к API: рейтинг, статистика, отчёты, команда, импорт, процессы, каталоги, доступ, интеграции, настройки, аудит.
- Единые поля выбора: оформленная раскрывающаяся панель на компьютере, панель снизу на телефоне, поиск в длинных списках, клавиатурная навигация, Radix-фокус и Escape.
- Мобильное боковое меню со всеми разрешёнными разделами; нижняя навигация сохранена.
- Две диаграммы радара открывают список взаимодействий с фильтром этапа/направления. Статистика выгружается в PNG на клиенте и PDF с сервера.
- Карточка: загрузка и скачивание документов, вложения перехода, заметки, состояние и ответственный, участники и импорт участников с предпросмотром.
- Новая запись, клиенты, контакты вуза, сохранённые виды радара и взаимодействий, доска текущей страницы и групповые переходы.
- Импорт: файл, кодировка, профиль, сопоставление, построчный предпросмотр, применение и итог.
- Процессы: нормы, подсказки, черновик, редактирование этапов/переходов и подтверждение влияния публикации; переименование ограничено ролью.
- Уведомления, адреса доставки и каналы; сообщения; серверная справка.
- API-клиент: FormData без JSON Content-Type, ответы 204, авторизованные скачивания и SSE. Мутации не повторяются автоматически.

## Проверки

- `npm test`: 50 тестов, 10 файлов, успешно, включая заключительный прогон.
- `npm run build`: TypeScript и Vite успешно, административные экраны вынесены в отдельный chunk.
- `git diff --check`: успешно.
- Браузер, режим MSW: главный экран и диаграммы, смена группы; нажатие «Подписание» открыло URL с `group=...&stage=signing`, в списке одна ожидаемая запись.
- Браузер, 390 × 844: список взаимодействий, рейтинг, меню со всеми разделами роли, закрытие меню при навигации. Поля не выходят за ширину экрана.
- Браузер, обычная ширина: оформленный выпадающий список пользователя, роль администратора, действующий процесс и нормы сроков.

## Что не подтверждено

- Живые операции с целевым бэкендом, PostgreSQL, MinIO, Redis, Keycloak и CI. Docker daemon недоступен. На порту 8000 работает другой CRM: `/api/health` отвечает, но `/api/v1/me` возвращает HTML другого приложения. Данные этого сервиса не менялись.
- Полный end-to-end импорта файлов, публикации процесса, прав доступа и получения настоящих XLS/PDF, доставки уведомлений и SSE в рабочем окружении.
- MSW расширен для чтения новых экранов и отдельных сценариев. Неимитируемая операция сообщает, что требуется подключение API; фиктивного успешного сохранения нет.
- Доска показывает текущую страницу, переход выполняется из карточки. Перетаскивание и офлайн-очередь заметок не реализованы.
- В контракте нет отдельного списка вендоров с ID: интерактивный список вендоров строится по продуктам. Вендор без продукта доступен через серверную выгрузку/импорт справочника. Для полноценного выбора/архивирования таких вендоров нужен отдельный каталог с ID на бэкенде.
- Справка отображает базовый Markdown и изображения с авторизацией. Внешние изображения и небезопасные ссылки не загружаются.

## Совместный интеграционный прогон

Запустить именно API этого репозитория и проверить `/api/v1/me` (JSON), затем `VITE_AUTH_MODE=dev npm run dev`. На синтетическом стенде проверить: создание записи → документ → переход с обязательным файлом → конфликт версии; импорт CSV/XLSX → предпросмотр → повторное применение; отчёт → событие завершения → скачивание; черновик процесса → предпросмотр → публикация; права трёх ролей и частичный результат групповых операций.

## Доработка дашборда и уведомлений

- Статистика: четыре KPI, согласованная группа для всех срезов, столбцы/кольцо для количеств, точки/столбцы для средней длительности, таблицы точных значений. Клик по этапу раскрывает долю и переход к отфильтрованным записям. На радаре направления по умолчанию кольцом при числе ненулевых категорий до шести.
- Вкладка динамики: переходы и средняя длительность завершённых посещений этапов; 30/90/180 дней, фильтр этапа, линия/столбцы, даты UTC. Для длительности пропуски остаются пропусками. Истории загружаются только при открытии вкладки, четыре запроса одновременно, отмена при смене группы. Ограничение: группы до 1000 доступных записей; для большего объёма нужен серверный агрегат. Неполная выборка не выдаётся за полную.
- Источники выбора графиков: [ONS](https://service-manual.ons.gov.uk/data-visualisation/chart-types/choosing-a-chart-type), [Datawrapper: временные ряды](https://www.datawrapper.de/academy/how-to-create-a-line-chart). Количества по текущим этапам не названы конверсией. Средние длительности не суммируются в круговую диаграмму.
- PDF: устранено перекрытие маршрута report обработчиком :kind в MSW. Деморежим формирует настоящий PDF по своей группе и правам, API-клиент проверяет MIME, сигнатуру и EOF. JSON/HTML больше не сохраняются как PDF. В рабочем режиме используется существующий серверный отчёт.
- Демоданные: длительности рассчитаны по синтетическим историям, одинаковые направления имеют общую идентичность. Статистика использует текущее состояние записей после переходов.
- Уведомления: сетка по ширине карточки, доступные switch-переключатели, состояния сохранения и ошибок, отдельные настройки пользователей. Исправлены hover отключённых основных кнопок и невидимые подписи кнопок заголовков на телефоне.
- Проверено в браузере: настольный дашборд, временная динамика, сохранение email в MSW, мобильные экраны 390×844, фильтрация по этапу с ожидаемой записью. PNG запускается без ошибки. Скачивание PDF возвращает подтверждение «Файл готов» после проверки файла.
- Проверка генератора PDF независимо от браузера: `mockStatsReport` с синтетическими данными, `pdfinfo` — три страницы A4, `pdftoppm` — все три страницы отрисованы и просмотрены, кириллица и подписи читаемы.
- Ограничения проверки: встроенный браузер не сообщает событие blob-download и блокирует открытие blob-PDF; фактический файл из его загрузок не подтверждён. Проверена та же функция генерации отдельно. Живой backend/CI не запускались; PDF сервера и реальная доставка уведомлений требуют интеграционного прогона.
- Финальный прогон: `npm test` — 65 тестов в 14 файлах; `npm run build` — успешно, основной JS 488 КБ, без предупреждения о превышении размера чанка; `git diff --check` — без ошибок. Статистика загружается отдельно от радара.
