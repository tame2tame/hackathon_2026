# Проверка экранов оплат и вендоров — 28.09.2026

Основа: локальная `main`, fast-forward до коммита бэкенда `c3d96ab`.
Постановка: разделы 10–11 `docs/FRONTEND_SCREENS_SPEC.md`.

## Реализация

- Клиенты → «Частные лица: оплаты и зачисление в LMS»: JSON/CSV/XLSX/XLS,
  кодировка CSV, обязательный предпросмотр, построчные результаты, применение.
  При смене файла или кодировки предыдущий предпросмотр сбрасывается.
- Выгрузка пользователей LMS с авторизацией, необязательными курсом и номером
  потока; ссылка на взаимодействия B2C на этапе `enrollment`.
- Каталоги → Вендоры: новый `/vendors`, ID, продукты, число контактов.
  Контакты загружаются при раскрытии вендора; создание и архивация — менеджеру
  и админу. Продукты выбираются только из продуктов данного вендора.
- Каталоги → Контакты вендоров (файл): импорт с предпросмотром и выгрузка XLSX
  через справочник `vendor-contacts`, только админу.
- Типы клиента перегенерированы из нового OpenAPI.

## Проверки

- `npm test` в `frontend/`: 15 файлов, 68 тестов прошли.
- `npm run build`: TypeScript и Vite успешно.
- `git diff --check`: успешно.
- `verification/payments-vendors.mjs`: браузерный прогон в headless Chromium
  против локального Vite (`VITE_AUTH_MODE=dev`, порт 5182), API подменён
  синтетическими ответами. Проверены:
  - multipart `dry_run=true/false`, сброс предпросмотра при смене кодировки;
  - ошибки строк и сводка, ошибка API с trace_id и повторная попытка;
  - авторизация скачивания и параметры курса/потока, запрет потока 0;
  - отсутствие запроса контактов до клика, создание и архивация контакта;
  - импорт/выгрузка справочника контактов;
  - скрытый импорт у КАМа, доступный у руководителя и администратора.
- Скриншоты обоих экранов просмотрены: таблицы и формы отображаются корректно.

Для повторения браузерного прогона нужен Playwright и его Chromium. При внешней
установке Playwright передайте путь к `index.mjs` через `PLAYWRIGHT_MODULE`;
нестандартный браузер — через `PLAYWRIGHT_EXECUTABLE`, каталог браузеров — через
`PLAYWRIGHT_BROWSERS_PATH`. Команда: `node verification/payments-vendors.mjs`.

## Границы проверки

Реальный сервер, миграция базы, содержимое сформированного бэкендом XLSX и CI
в этой задаче не проверялись. Браузерный прогон проверяет интерфейс и запросы,
а не расчёты бэкенда. В автономном демо неподдержанные операции, как и раньше,
возвращают явное предложение подключить API. В удалённую `main` ничего не отправлено.
