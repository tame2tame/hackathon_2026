### Статус бэкенда на 20.09

- **Закрыты задачи B-28 — B-35.** Состояние записи (пауза, завершение, отмена, возврат), ручные приоритеты курсов, кэш действий пользователя, списки обучающихся и преподавателей, сохранённые виды списков, диаграммы связей, программно-аппаратной архитектуры и БД. Из «мелочей» жюри не взят только отдельный механизм фича-флагов — вместо него в [`ARCHITECTURE.md`](../ARCHITECTURE.md) описано, что и чем выключается.
- **Проверки:** 305 тестов, ruff и mypy без замечаний, контракт совпадает со схемой приложения (100 путей, 114 методов), в базе 46 таблиц; `alembic check` расхождений не видит, миграции проходят вниз и вверх.
- **Проверено на живом окружении:** кэш на настоящем Redis (попадание, сброс поколения, работа при отказе) и на запущенном API (`304` без тела, рейтинг 150 мс против 6–9 мс); копия файлов из MinIO — семь объектов, повторный запуск не перекачивает ничего; smoke-скрипт показывает состояние хранилища; нагрузка после B-28 — B-33: p95 386,59 мс при 50 пользователях, максимум 908 мс, ноль ошибок из 21 048 запросов, 10 отчётов из 10 доведены до `done` ([`LOAD_TEST.md`](LOAD_TEST.md)); три диаграммы отрисованы mermaid без ошибок; запас по нагрузке измерен до 300 пользователей (ошибок нет ни на одной ступени, упирается база, а не приложение — разбор и план масштабирования в [`LOAD_TEST.md`](LOAD_TEST.md)); весь набор B-28 — B-34 проверен на чистой базе (миграции с нуля, полная загрузка v1: 351 запись, демо-группа обучающихся, пауза с причиной, ручной приоритет, сохранённый вид, переписка, выгрузка списка и загрузка её обратно без изменений).

## Готовность задачи

- Критерии приёмки из Issue выполнены и проверены командами, указанными в PR.
- CI зелёный, новые тесты покрывают изменение.
- Контракт, `ARCHITECTURE.md` и документация обновлены, если изменение их касается.
- Нет секретов, реальных персональных данных и отключённых проверок.
