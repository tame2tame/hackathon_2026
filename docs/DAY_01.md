# Итог 15.09 и следующие шаги

## Выполненный объём

План архитектуры отводит фронтенду в день 1 скелет Vite + shadcn/ui, тему и роутинг. Этот объём выполнен; дополнительно реализованы локальный радар, список/сетка взаимодействий, карточка с переходом и историей, вузы, справка. Созданы Button на Radix Slot/CVA и диалог Radix; `components.json` позволяет дальше расширять shadcn/ui. Это базовые компоненты, не полный UI-kit.

## Структура

- `frontend/src/App.tsx`: оболочка, маршруты, страницы первого дня; при развитии выделять страницы в отдельные модули.
- `frontend/src/lib/data.ts`: синтетические фикстуры и чистые функции демо.
- `frontend/src/lib/data.test.ts`: тесты области видимости и переходов.
- `frontend/src/components/ui/button.tsx`: общий Button.
- `frontend/src/styles.css`: токены/оформление/адаптивные состояния.
- `frontend/src/main.tsx`: роутер и QueryClientProvider.
- `.github/workflows/frontend.yml`: npm ci, тесты, typecheck и сборка.

## Что нужно от команды

1. Создать общий GitHub-репозиторий и прислать ссылку. После этого перенести `frontend/`, `docs/` и workflow без перезаписи файлов бэкендера. Папка сейчас не является git-репозиторием.
2. Вместе с бэкендером утвердить `ARCHITECTURE.md` и `contracts/openapi.yaml` v0. Полную архитектуру из интервью не копировали как якобы заново согласованную; изменения контракта не выдумывали.
3. Для 16.09 получить адрес API, Keycloak URL/realm/client ID, redirect URI и название claim с ролями. Секрет клиента в SPA не нужен: public client + PKCE.
4. Запросить у организаторов XLS/XLSX-пример и контракты LMS/сайта, когда их выдадут. Это нужно для настоящего маппинга и интеграций.

Ничего покупать или публиковать для локальной проверки не требуется.

## Предложение к обсуждению API v0 — не утверждённый контракт

- Профиль: user ID, full_name, role, team, область видимости; сервер фильтрует каждый запрос.
- Справочники: отдельные ID вузов, программ, продуктов, пользователей.
- Взаимодействия: пагинация/фильтры, текущий этап, версия записи, КАМ, версия workflow.
- Карточка: история, допустимые переходы и требования к комментарию/документам.
- Переход: ожидаемая версия записи для защиты от конфликтов, comment, attachment IDs; результат и ошибки.
- Сигналы: kind, severity, evidence, interaction ID, дата обнаружения/закрытия.
- Ошибки: application/problem+json, code, detail, trace ID, field errors.
- События: формат SSE, авторизация подключения и восстановление после потери связи.

## Ограничения

Нет настоящей авторизации, сети/API, общих изменений между пользователями, файлов и долговечной серверной истории. Демо-роль не является защитой данных. Данные лицензий зафиксированы на дату 15.09.2026 и не пересчитываются ежедневно. Университеты в фикстурах представлены одной связкой; до API нужно заменить временные ID на независимые university_id. Серверные проверки, 50 пользователей, 10 отчётов, юридическое соответствие и полный сценарий «4 акта» ещё не проверяются.
